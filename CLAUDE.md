# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Delve is an idle/incremental pixel-art dungeon-crawler game: HTML/CSS/ES-module JS built with Vite. Long-term plan: mobile apps via Capacitor, plus a backend for cross-platform cloud saves and later purchases (backend choice — Firebase/Supabase vs Next.js on Ruust — is still undecided). Git: private repo https://github.com/harry4041/delve (branch `main`, remote `origin`); commit and push only when asked. `Delve.html` (original single file) and `legacy/` (the split classic-`<script>` version) are old backups, not the source of truth.

## File layout

`index.html` is the markup shell (`#battle`, `#camp`) plus a single `<script type="module" src="/src/main.js">`; `src/main.js` imports `style.css` and boots the game. Everything in `src/` is an ES module with explicit `import`/`export` lines at the top of each file (generated by a one-off migration script, so **a name is only exported if another module used it** — add `export` when you start sharing something).

Module groups: `state` (helpers, rarity/slot tables, `def/load/save`, shared mutable vars + setters) · `items` (loot rolling, `gen`, `val`, `sc`) · `sets` · `auras` · `stats` (`powerLevel`, `stats()`, forge, offline calc) · `skilltree` (`TREE` node data, `GRAPHS` web definitions, bag/vault costs) · `treeview` (skill-tree SVG web renderer) · `ascension` (relics, `ascend`, pets) · `gear` · `tabs-aura-idle` · `vault-leaderboard` · `battle` (`startRun`, `spawn`, `tick`) · `render` (canvas drawing, `hud`, `loop`) · `icons-data` (one ~270 KB line of base64 PNGs: never print or Read it in full) · `assets` · `camp` (`view`, `camp()`, click dispatcher) · `main`.

Code is dense minified-style JS (many statements per line).

### Module gotchas (important)
- **Circular imports are everywhere.** Evaluation order is decided by the import graph, not by file order. Top-level `const x=(…)=>…` helpers were converted to hoisted `function` declarations specifically so modules can call each other during start-up (e.g. `render.js` runs `const cv=$('#c')` at load, before `state.js` has evaluated). Keep shared helpers as `function` declarations. A top-level **data** `const` (array/object) used at load time by a *different* module can still hit a TDZ error ("Cannot access X before initialization"); use it only inside functions, or move it earlier.
- **Cross-module writes need setters.** An imported binding can't be assigned from another module. Shared mutable state lives in `state.js` (`S, run, mode, tab, uid, forgeMode, forgeSelected`); other modules write via `setS/setRun/setMode/setTab/setUid/setForgeMode/setForgeSelected` and `nextUid()` (replaces `uid++`). Reads and member writes (`S.gold+=1`, `run.hp=0`) work directly. Don't write `run = …` in a module other than `state.js`.

## Architecture

All state lives in one global `S` (save object, built by `def()`, normalised in `load()`, persisted by `save()` to `localStorage` key `hollow-delve-2`; a separate leaderboard uses key `hd-lb`). Changing the save shape means updating `def()` **and** the migration/defaults in `load()` so old saves keep working. `run` holds transient per-delve combat state and is not saved. `mode` (`'camp'|'battle'`) and `tab` select which view renders.

Flow:
- **Game loop:** `requestAnimationFrame(loop)` (`src/render.js`) calls `tick(dt)` (combat sim, run `maxSpd()` times per frame for speed-up), `draw()` (canvas pixel-art rendering with the `R`/`spr`/`put` helpers and sprite string-maps like `CH`, `SKM`), `hud()`, and autosaves every ~5 s.
- **Combat:** `startRun` → `spawn` (enemy scaling via `hpG`/`atG`; boss every 10th stage) → `tick`/`dmgEnemy`/`kill` → `die`. Player stats are always derived from `stats()`, which folds in gear, the upgrade tree, auras, set synergies, ascension bonuses (`ascB`), pets, and ascension modifiers — add new stat sources there.
- **Items:** `gen()` creates items from rarity index `ri` (`RN`/`RC`/`RM`/`RW` tables), item level `il`, sub-level `lv` (I–III), base-type tables (`BASE`, `TT`, `SPEC`, `SUFS`, `PRE`, `W` stat weights). `sc()` scores items for auto-equip; `val()` is sell value; `forgeDo`/`forgeAll` merge duplicates upward.
- **Progression layers:** gold upgrades (`TR`, and the `TREE` skill-tree nodes keyed by `k`, helper `L(k)` = level; `can`/`cost` gate purchases), gems → auras (`AURAS`), Ascension prestige (`ascend`, `relicGain`, relic tree `RTREE` with `RL(k)`, milestones `ASC_MS`, per-run `ASC_BUFFS`/`ASC_DEBUFFS`), vault, pets (`PET`), idle/offline earnings (`offlineCalc`, `idleTab`), and local leaderboard (`lbSave`/`lbTab`).
- **UI:** no framework. Each tab is a function that builds an HTML string and assigns it to `#cbody` (`camp()` dispatches; `auraTab`, `idleTab`, `vaultTab`, `ascTab`, `lbTab`, `tree`, etc.).
- **Skill trees:** the Upgrades, Magic and Pets tabs each render one hub-and-spoke SVG web via `tree(GRAPHS.u|m|p)` in `src/treeview.js`. `GRAPHS` (in `skilltree.js`) lists each web's hub and its compass arms (`N/E/S/W`, colour var, node keys). A node's parent in the drawing is its deepest prerequisite **inside the same arm** (else the hub), so prerequisites in `TREE` should stay within an arm (a hub such as `arcana`/`den` may be a prerequisite from outside); arms with several roots get a junction dot. Layout is a tidy-tree computed once per graph, with a wedge rule (`TV_WEDGE`): a node is pushed outward along its arm until its sideways offset fits inside its own 90-degree wedge, so wide arms never overlap neighbours. **Visibility:** a node is only drawn once you own it or all its prerequisites are met (`tvVisible`); the hub is always shown, a junction dot only if one of its roots is, an arm label only if the arm has something showing, and Fit/initial zoom use the visible bounds. Positions come from the full layout, so nodes simply appear in place. **Connectors** are right-angle elbows (`<polyline>`, never diagonal): along the arm, across, along again, with the bar placed in the clear gap between a parent circle and its child's label (`.3` of the way for N arms, `.7` for S, mid-way for E/W). Node look: circle = levelled node (with a progress ring when capped), diamond = one-off unlock (`m===1`), hexagon = Mastery (`/^m[A-Z]/`), pulsing gold ring = affordable now. pan/zoom/selection live in `tvS` and survive `camp()` re-renders. Tapping a node shows a panel whose Buy button reuses the `data-a="tr"` action.
- **Cloud saves:** `src/cloud.js` (lazy-loaded Firebase Auth + Firestore, one doc `saves/<uid>` = `{v,data(JSON string of S),clientT,summary,updatedAt}`), `src/account.js` (Account tab UI + its own `data-c` click/submit listeners), `src/firebase-config.js` (public web config). Local-first: `save()` always writes localStorage, then calls the hook set by `setSaveHook` which schedules a push (45 s throttle, also on page hide). Sync on sign-in: no cloud doc -> upload; fresh local -> apply cloud; cloud unchanged since last sync (`hd-cloud-base`) -> push; local untouched since last sync -> apply cloud; otherwise a conflict is shown and the player chooses (old local save backed up to `hollow-delve-2-backup`). Pushes are Firestore transactions that refuse to overwrite a cloud doc another device changed. `firestore.rules` (also holds `gifts`, `lb`, `banned`; NOTE the `lb`/`banned` rules were written 2026-11-12 but their deploy was not authorised yet: until `deploy --only firestore:rules` runs, the Firestore default for unknown paths is deny, so leaderboard reads/writes fail with permission errors) only allows a verified user to read/write their own doc with a fixed field set. `cloud.js` emits `hd-cloud` window events; `main.js` re-renders on them. Never swap saves mid-run (`mode!=='camp'` defers).
- **Upgrade mechanics (hooks):** Vampirism/Evasion/Deadly aim + masteries Grit/Haste/Fury/Aim are folded into `stats()`; Opening strike/Boss slayer/Executioner/Mastery Slaying multiply hero hits in `heroMult()` (battle.js); Rampage keeps `run.rn/rt` (stacks, timer) and speeds the hero attack interval; Bulwark and Second wind (`run.swUsed`, `run.swT` for the flash) live in the enemy-attack line of `tick`; Gem hunter/Bounty/Golden goblin (`run.golden`) are in `spawn()`/`kill()`; Efficient forge/Lucky forge in `forgeCost`/`forgeDo`; Appraiser in `val()`; Relic channel in `relicGain()` (ascension.js); Mastery Recovery counts as extra Recovery levels in `kill()`. Node data is in `TREE` (skilltree.js) and each node must be listed in an arm of `GRAPHS` and have a `treeVal()` label (gear.js).
- **Pets:** only ONE pet is active (`S.ap`); the roster is `PET` in `state.js` (order matters: indexes 0-2 are the original Pip/Fang/Ember so old saves stay valid, 3-5 are Moss/Coin/Spark; `load()` pads `S.pets` to `PET.length`). Each pet has a base damage fraction `d` per `iv` seconds, a cost, a level-cost tier `t`, and a signature ability implemented in `src/pets.js` (`petFx()` -> numbers; `petInfo()` -> UI text) and applied by hooks in `battle.js` (`petTick` for the pet's own attack, Pip slow + Moss redirect in the enemy-attack line, Coin gold/loot in `kill()`/`spawn()`, Spark mana/cooldown/haste/spell bonus in `tick`/`spellFx`, Ember burn via `run.pb` ticked in `dots`). Abilities scale with pet level/stars (`petScale`) and with a build stat: Pip=Vigor, Fang=your crit, Ember=Arcana+Fire, Moss=Grit, Coin=Greed, Spark=Arcana. 12 signature nodes (`pipSticky`... `sparkOver`) sit in the Signatures (W) and Kennel (S) arms of `GRAPHS.p`. All pet numbers live in `petFx()` and the `PET` table.
- **Balancing pets:** `tests/balance.html?runs=20&plvl=6&sig=0&scales=1.2,1.5,1.8,2.1` auto-plays hundreds of runs for 6 hero builds x (no pet + 6 pets), averaged over build strengths, and prints % change vs no pet for progress (stage + how far into the killer enemy), gold/min and loot value/min. Design targets, all met at the last tuning: Moss leads thorn/tank progress, Pip leads sustain/squishy progress, Fang leads crit, Spark leads support mage, Ember leads fire-mage gold, Coin leads economy gold; off-build Coin must not lead gold. Known caveats: a high-Vigor + high-Recovery hero can be effectively immortal (runs hit the 25 min cap), hero-level pets multiply base damage ~5.7x at level 6, and results are noisy (use runs>=20). `?sig=3` gives every pet its two signature nodes at level 3; `?plvl=2&scales=0.4,0.6,0.8` checks early game.
- **Cost/size controls (Firestore bills per write, docs cap at 1 MiB):** pushes every 5 min max (`PUSH_DELAY`) plus on page hide, skipped when only `lastT` changed; the save is gzip+base64 (`enc:'gz1'`; docs without `enc` are legacy plain JSON); if still > `MAX_DATA` (900k chars) the **cloud copy** drops the lowest-`val()` bag items (local save stays whole); `firestore.rules` also refuses writes < 60 s apart and caps `data` at 950k. Measured: one item ~95-185 B JSON; 2000 items = 533 KB raw / ~237 KB as base64 gzip. Spark plan = no card, 20k writes + 50k reads/day, 1 GiB; Hosting 360 MB/day transfer. Known risk: the top bag tier is unlimited (`BAG_CAPS` ends in `Infinity`) and `save()` swallows localStorage quota errors (~5 MB, roughly 9,000 items), so a huge bag can stop saving locally.
- **Gifts:** `src/gifts.js`. You create docs in the Firebase console: `gifts/global` (everyone) or `gifts/<uid>` (one player), each `{gifts:[{id, note?, until?(ms), gold?, gems?, gen?:[{ri,il,n,ty?,lv?}], items?:[{ty,ri,il,lv?,nm,st:{atk|def|hp|crit|spd|ls|dodge|gf|thorn|mpr|poison}}]}]}`. Players cannot write them (rules). Claimed ids are stored in `S.giftsClaimed` (synced), so each gift is applied once per account; everything from the server is validated/clamped (item names must match `[A-Za-z0-9 '’-]{1,48}` and include a base-type word such as Crown/Sword so the icon shows). Checked after each sign-in sync (max every 6 h) and via the Account tab button. Clients are trusted for the save itself, so gifts are not cheat-proof; anything worth money should later move to server-side (Cloud Functions) logic.
- **Battle scene module:** `src/scene.js` (readable, multi-line style, takes the context `g`, no dependency on render.js) draws everything except the characters themselves: `drawBackdrop` (shared bricks/pillars/torch/perspective floor + one function per zone in `ZONE_FX`: Crypt, Fungal Warren, Ember Hall, Drowned Vaults, Infernal Pit, Void Sanctum, each with scenery and ambient particles), `drawShadows`, `drawForeground` (vignette, void fog, boss red pulse), `drawEffects` (slash arc coloured by weapon rarity, hit sparks, crit starburst, spell effects from `run.vfx` entries `fire|heal|frost|meteor|death`), plus `drawCape` / `drawHeroAura` (rune circle + sparkles scaling with the best equipped rarity) / `drawMobFx` (boss menace aura, glowing eyes on cultists and bosses). Timers it reads on `run`: `lunge, ef, critT, shakeT, petT, swT, vfx[]` (initialised in `startRun`, advanced in `tick`). Item icons are tinted in `assets.js` with an overlay blend (keeps shading) plus a light flat tint; the old flat tint washed high rarities into silhouettes. The 29 base item icons are already good hand-made pixel art, so they were left alone.
- **Battle graphics:** the canvas is 192x108 drawn on a 96x54 logical grid (`g.setTransform(2,...)`). Pets are pixel sprites (`PET_SPR` + `drawPet` in render.js, one map per pet key); effects: burn flames under the enemy (`run.pb`), gold frame + sparkles on golden enemies (`run.golden`), gold flash on Second wind (`run.swT`), orange chevrons above the hero per Rampage stack (`run.rn`). To preview art, build a throwaway page like the ones in `tests/` and screenshot it with headless Edge (`--screenshot`); remember `style.css` forces `canvas{width:100%;aspect-ratio:16/9}`, so give preview canvases inline sizes.
- **Backpack filter/sort:** `src/backpack.js`. The gear tab passes the game's default-ordered bag (`bag0`, which still honours the Bag sorting upgrades) through `bpView()`; `bpControls()` prints three selects (rarity with counts, type with counts, sort: price asc/desc, rarity, item level, biggest upgrade) and a Clear button; paging via `data-bpa="more"` (60 per page). Choices persist in localStorage `hd-bp`; changes emit `hd-bp` and main.js re-renders the gear tab.
- **Pet farm:** `src/farm.js`. Owned pets that are not `S.ap` rest on the farm and earn in real time: gold/h = `3600 * idleKg() * farm.g * (1+.2*lvl) * (1+.5*stars)` plus gems/h for Moss and Spark (`PET[i].farm = {n, g, gem}` in state.js). Banked in `S.farm {t, gold, gems}`; `farmSettle()` credits at most 8 h since `S.farm.t` and restarts the clock, so it MUST be called before anything that changes who is resting (`ap`, `bp` actions already do); `farmCollect()` pays out whole gold/gems and keeps the fractions. UI box is `farmHtml()` in the Pets tab (hidden until the Pet den is bought).
- **Farm tuning (2026-11-12):** `GOLD_PER_HOUR` went 120 -> 3600 after `tests/career.html` showed the farm paid ~1% of active income; it is now ~15-20% in the first hours (8 h cap unchanged). Re-measure with the career bot's `ECON` line after touching hero gold or `idleKg`.
- **Auto-delve:** `S.autoDelve` (saved, default off). Toggle buttons `#autob` (battle row) and `#autoo` (defeat overlay) emit `data-a="auto"`. The render loop counts `run.ot` while `run.over` and, once it passes `AUTO_DELAY` (1.5 s) with the setting on and the player still in battle mode, calls `delveAgain()` (camp.js: banks the loot, trims the bag to its cap by selling the cheapest, then `startRun()`). It never fires from camp. It does not buy upgrades or equip gear. `hud()` tolerates the buttons missing because the test pages carry an older copy of the HTML shell. Test: `tests/autodelve.html` (18 checks).
- **Leaderboards (Scores tab replaced):** `src/leaderboard.js`, Firestore collection `lb/<uid>` = `{v, name, stage, power, asc, stars, t}`, opt-in (player picks a public name stored in `S.lbName`, synced with the save). Sub-tabs: Deepest stage, Power level, Ascensions, Pet stars, plus **My runs** (the old local `hd-lb` history). Reads: top 25 per board, cached 10 min, manual refresh min 60 s (cost: 25 reads per board view; no count/rank queries because those would need unbounded list access). Writes: `publish()` runs after each cloud sync/push via `setAfterSync`/`setAfterPush` (both are now lists in cloud.js), at most every 10 min and only when something changed. Names: 3-18 chars `[A-Za-z0-9 _.'-]`, a small leet-aware blocklist (known false positives such as "Scunthorpe").
- **Cheating (important):** the game and saves live in the player's browser, so every score is self-reported and cannot be proven. Defences: `firestore.rules` (`lb`) require a verified owner, an exact field set, integer bounds (stage<=5000, power<=1e8, asc<=500, stars<=500), `t==request.time`, >=5 min between writes, values that never decrease, stage growth <= 100 + 10/min and asc <= +5 per publish, and a `banned/<uid>` document (create it in the console) blocks an account. To remove a cheater: delete `lb/<uid>` and create `banned/<uid>`. NOT defended: a first publish with any value inside the caps, or slow plausible inflation. Real protection needs server-side verification (Cloud Functions on the paid Blaze plan, recomputing from the synced save or replaying progress) and is not built. The same trust limit applies to gifts, saves and everything else client-written.
- **Click handling:** all other interaction goes through one delegated `click` listener at the end of `src/camp.js`, dispatching on `data-a` (action) and `data-v` (value) attributes, then `save(); camp()`. To add a button: emit `data-a="x"` in the tab HTML and add an `if(a=='x')…` branch in that listener.

## Gotchas

- **`def()` must build every roster-sized field from the data tables** (`pets:PET.map(...)`, `giftsClaimed:[]`): "Reset save" assigns `S=def()` without going through `load()`, so anything only padded in `load()` is missing afterwards.
- **Battle speed lives in the render loop only:** `loop()` calls `tick(dt)` once per speed step, so nothing inside `tick()` may multiply by `S.speed`/`maxSpd()` (cooldowns did, and ran at speed^2).
- **Ascension buffs/debuffs must be plain additions or multipliers**; `stats()` applies the caps (speed 3.5, crit 75, dodge 50) afterwards and converts the overflow into bonuses, so clamping inside a buff throws bonuses away.
- **Enemy growth per stage** is `hpG = min(1.25, 1.22+.003*asc)`, `atG = min(1.24, 1.22+.002*asc)` (ascension.js); steeper values made stage-50 bosses ~158x tougher at ascension 10 while the hero gained ~1.6x.
- `st._spellBonus` (Arcane Scholar) multiplies spell damage and Mend in `spellFx`; `st._luckBonus` (Lucky Wanderer) adds to the per-roll drop chance in `spawn()`.

- Large numbers are displayed with `fmtN`; late-game values can reach exponential range, so keep new math finite-safe.
- Several systems exist in near-duplicate form (e.g. `rollR`/`rollStep`, `petLc` vs. an inline pet cost in the Upgrades tab, `auraCost` vs `auraUpCost`); check which one is actually called before editing.
- There is no unit-test suite; verify changes with the smoke test above and by loading the page and checking the console for errors; a stale save can be cleared with the in-game "Reset save" button (or removing `hollow-delve-2` from localStorage).
